## 1. Mission

Build the strongest practical two-computer intelligence system we can prove today:

- N150 owns deterministic control, health, routing, receipts, memory access, and service continuity.
- Codexa owns model inference, large embeddings, specialist leases, training, and batch evaluation.
- Bun owns the control plane.
- Models propose cognition; they do not own truth, execution state, routing law, or receipts.
- Every important claim is tied to a live probe, source pointer, deterministic test, or governed receipt.
- Every failure improves routing, memory, a validator, a reflex, or a falsifier.

The goal is not a larger chatbot. The goal is a **proof-directed intelligence operating system** that stays on project, uses the right intelligence class, remembers why, sees current reality, learns from failure, and never presents theater as execution.

## 4. New Core Innovations

### 4.1 Capability Covenant

Every request receives a machine-readable minimum intelligence class:

- `general`
- `code_specialist`
- `architecture_judge`
- `visual_judge`

The covenant defines minimum tier and fallback rights. Architecture, code, and visual specialist work may not use a shared hot fallback. A draft is checked for domain coverage and substance. One bounded repair is allowed. A second failure becomes an honest blocked report.

### 4.2 Context Crystals

Orange compiles a task-specific working set from the real project corpus:

- source path
- byte range
- source hash
- chunk hash
- relevant AIR excerpt
- reconstruction pointer
- required authority retention

This is not a hidden answer cache. It is a source-verifiable compiled workbench. The source can be reopened and the crystal invalidates when truth changes.

### 4.3 Proof-Directed Work Graph

Work is represented as state transitions:

```text
unknown -> observed -> hypothesized -> tested -> proven -> promoted
```

Each transition requires evidence. Models can propose transitions; Bun validates them.

### 4.4 Receipt-to-Reflex Compiler

Repeated high-confidence receipts become candidates for deterministic reflexes only when:

- the input shape is stable
- the outcome repeats
- no counterexample survives
- the action is bounded and reversible
- the generated rule passes held-out tests

The output is code plus tests, not a vague memory note.

### 4.5 Failure Memory

Failures are stored as reusable operational knowledge:

- triggering state
- attempted route
- observed failure
- falsifier that caught it
- repair
- recurrence guard
- source and receipt pointers

Failure memory changes future routing only after deterministic evaluation.

The active implementation is outcome-aware: correct evidence/approval stops are
stored as guarded decisions rather than failures, proven outcomes close older
failure episodes, later failures reopen them, and the hot path reads a bounded
newest-first Flux tail instead of replaying historical partitions.

### 4.6 Current-Awareness Organ

Current knowledge is separate from identity and project truth:

- primary-source research registry
- observed timestamp
- source hash
- capability impact
- local suitability
- benchmark requirement
- quarantine until proof

New tools never become active because they are fashionable. They become active when they beat the incumbent on a real Orange workload.

## 5. Compression Standard

The target is **200x operational context/work compression**, not a universal claim of 200x lossless byte compression.

Required measurements:

- raw corpus bytes and estimated tokens
- injected workbench bytes and estimated tokens
- source pointers preserved
- required authority retained
- reconstruction verification
- task quality before and after compression
- latency and model-call cost

Promotion requires both reduction and retained task performance.
