# Atomic Orange Dock Standard

Status: live product law

Purpose: Atomic Orange is the Orange5-native fork/edition of the Atomic Chat idea. It should preserve the useful Atomic Chat product path while binding every capability to AtomEons / Orange5 operating contracts.

## Core Position

Atomic Chat is the upstream inspiration and compatibility target.

Atomic Orange is the AtomEons command surface built from that class of product:

```text
Atomic Chat feature class
-> Atomic Orange UI affordance
-> OrangeBrain gateway contract
-> Orange5 pillar or Hermes lease
-> receipt-backed report
```

No Atomic-style feature is allowed to become an ungoverned bypass.

## Required Mapping

| Atomic feature class | Atomic Orange expression | Orange5 destination | Product rule |
|---|---|---|---|
| Local model chat | Chat lane + brain selector | OrangeBrain `/v1/chat/completions` | UI never calls a provider SDK directly. |
| OpenAI-compatible server | `127.0.0.1:1337/v1` gateway | OrangeBrain | This is the app's only model API seam. |
| 1000+ model catalog | Model dock / future browser | OrangeBrain model registry | Browse many, promote few, receipt every promotion. |
| Cloud model keys | Frontier setting | OrangeBrain frontier proxy | BYO keys stay local; frontier isolation remains law. |
| Custom assistants | Settings custom rule + Orange assistant policy | OrangeBrain system policy | Assistant rules compile into Orange order/report discipline. |
| Projects and conversation trees | Recent projects + Project Galaxy + Vault | Atomic Orange + AE Memory | Projects are operational contexts, not loose chats. |
| Persistent memory | Vault, recall chips, receipt rail | AE Memory / AE Cobra | Memory must cite receipts or source pointers. |
| MCP servers | MCP dock / Hermes route | Hermes MCP router | Tools require leases, risk policy, and receipts. |
| One-click agents | Agent dock | Hermes leases | Agents are hands, never hidden rulers. |
| Artifacts/live preview | Vault artifacts + AE Eyes | AE Eyes + receipt trail | Visual/artifact output needs proof, screenshot, or receipt. |
| TurboQuant / llama.cpp / local engines | Model engine status | OrangeBrain model registry | Engine adoption needs local benchmark and rollback path. |
| Offline/private mode | Egress mode + boundary badges | Orange5 boundary policy | Default posture is loopback/local-first. |

## Four-Lane Placement

Atomic Orange keeps the four-lane law.

| Lane | Atomic capabilities hosted here |
|---|---|
| Chat | OpenAI-compatible conversation, assistant rules, model selector, order/report wrapper. |
| Cockpit | Live system state, project galaxy, model routing, agent/receipt/visual status. |
| Vault | Memory, artifacts, receipts, project context, source-backed retrieval. |
| Settings | Model dock, MCP dock, custom assistant rules, egress/profile controls. |

No fifth lane is created for Atomic compatibility.

## Forever Rule

When upstream Atomic Chat adds a feature, Atomic Orange evaluates it by this sequence:

```text
1. What capability class is it?
2. Which Orange5 pillar owns it?
3. Which gateway route or Hermes lease makes it safe?
4. What receipt proves it works?
5. Where is it shown in the four-lane UI?
```

If those five answers do not exist, the feature is a research dock item, not a live Orange capability.

## Current Handshake

Atomic Orange already has:

- Tauri v2 + React/Vite native app shell.
- Four lanes: Chat, Cockpit, Vault, Settings.
- Chat lane wrapping requests as `orange.order.v1`.
- OrangeBrain-compatible OpenAI endpoint at `127.0.0.1:1337/v1`.
- Cockpit AESee-lite visual surface.
- Settings controls for brain tier, custom assistant rule, egress, and Orange running indicator.
- Vault/memory/receipt surfaces.

Required next product work:

- Add visible Atomic Dock status to Settings.
- Add model/MCP/agent/artifact connection status without adding a fifth lane.
- Keep Atomic Chat upstream compatibility as a first-class product principle.
- Keep all heavy execution behind OrangeBrain/Hermes/receipts.
