## 2. System Definition

Æ Orange AI Computer is a local-first AI computer control plane. It separates:

- replaceable operator interfaces;
- deterministic policy and evidence;
- model cognition;
- bounded execution;
- durable memory;
- context/work compression;
- visual and creative workers;
- current research and governed learning.

The architecture prevents a fluent model response from becoming operational
truth without execution evidence.

## 3. Topology

### Preferred two-computer topology

```text
N150 control host
  Bun Navigator Kernel
  canonical spine
  Brain MCP
  receipts and project continuity
  operator clients
          |
          | authenticated rail / governed model transport
          v
Codexa heavy host
  Orange Navigator
  code and judgment specialists
  AE Eyes workers
  Docker services
  training and long jobs
  creative model library
```

N150 requires no resident answer model. Codexa models are lease-loaded. Disk
holds the library; RAM holds the current working team.

### Single-computer topology

The same control plane can run on one Windows host. Hardware discovery must
select only roles that fit. Deterministic functions remain available when no
local answer model is installed. Heavy roles may be disabled or delegated to
an optional hosted lease.

This is an architecture-supported mode. Generic public clean-install and
arbitrary-hardware proof must still be established by release testing.

## 4. Operational Crossing

```text
orange.order.v1
-> schema and lease validation
-> LOOM policy and approval gates
-> Project Lock and Continuum
-> least-action and compute-fabric route
-> AE Memory recall
-> Context Crystal / AtomSmasher workbench
-> Navigator or specialist inference
-> adversarial or epistemic review when required
-> deterministic executor or Hermes lease
-> post-output verification
-> orange.report.v1
-> hash-chained receipt
```

No missing organ may silently become successful execution. A failed execution
boundary returns `needs_action`, `executed: false`, and named evidence.

## 5. Contracts

### Input: orange.order.v1

Core fields include order identity, action, payload, scope, allowed actions,
forbidden actions, target project, risk, approval posture, and receipt
requirement.

### Output: orange.report.v1

Core fields include status, confidence, actual actions, evidence, blockers,
next action, and receipt provenance.

Model-facing packets may use a compact private codec. Bun expands them into the
public report. The model cannot supply trusted order identity, execution
attestation, or receipt authority.

Explicit caller evidence defaults to exact preservation. Drift downgrades a
completion claim and sends it to governed verification. Derived evidence is
reserved for the authorized internal falsifier path.

## 6. Control Plane

### Bun Navigator Kernel

Bun owns the hot deterministic path:

- validation and public schema;
- policy and approval boundaries;
- route and fallback selection;
- service health;
- receipt composition;
- common repeated work;
- replay and bounded learning.

Bun was chosen for low startup overhead, a compact TypeScript/JavaScript
control surface, and alignment with the gateway and native app stack. Bun is
not a model and does not need model RAM.

### Canonical Spine

Entry point:

```powershell
bun C:/AtomEons/Orange5/03-BACKEND/spine-cli.mjs
```

The spine preflights the order, consults memory and compression, attempts a
real gateway or deterministic executor, applies adversarial review when
required, and writes a receipt only outside dry-run mode.

### Brain MCP

The Brain MCP server exposes governed tools, resources, and prompts.

- stdio transport supports desktop and IDE clients.
- Streamable HTTP is loopback-only by default.
- HTTP validates protocol, method, and resource/tool-name metadata.
- request bodies are bounded.
- side-effecting notifications receive no execution channel.
- durable MCP Tasks support current protocol clients.

Current proof observes 10 tools over stdio and 12 over authenticated loopback
Streamable HTTP. Transport-specific tool counts need not be identical.

The MCP boundary is an adapter to Orange, not a shell bypass.

## 8. Execution Plane: Hermes

Orange uses two related Hermes surfaces:

1. The Orange Hermes effector and LOOM code under `08-HERMES`, which provides
   current bounded execution tests and runtime paths.
2. The official Hermes Agent product integration under
   `08-HERMES/product-integration`, pinned to an immutable upstream release.

The product integration is designed for:

- six isolated profiles;
- one gateway owner;
- one durable Kanban dispatcher;
- an authenticated loopback OpenAI-compatible API;
- a filtered Orange Brain MCP surface;
- one conductor plus at most two active specialists;
- flat delegation depth and no nested orchestration tree.

Hermes profile isolation is not an OS sandbox. Toolsets, Orange orders, LOOM,
and optional container isolation enforce the practical boundary. Builder is
the only profile with direct mutation tools. Kanban `done` is workflow state;
only an Orange receipt proves operational completion.

Current capability configuration marks durable Kanban and other product
features as configured until a fresh preflight proves them live.

The fresh Hermes Brain MCP delegation receipt proves a complete harmless read
crossing through parent execution, one child, synthesis, and lease revocation.
Mutation, multi-child, and long-job routes retain independent proof contracts.

## 9. Memory And Continuity

### AE Memory / Cobra

Stores durable project facts, decisions, failures, and evidence on disk. It
combines lexical, dense, and hybrid retrieval and records contradiction debt.
Current held-out quality is 23/23 cases with hybrid MRR `0.9058`, p50 `281 ms`,
and p95 `445 ms`. Hybrid beat both lexical-only and dense-only ablations.

### Project Continuum

Preserves cold source, transcripts, and lineage; performs duplicate-work
preflight; hydrates only the relevant task workbench.

### Receipt-to-Reflex

Repeated, proven work may become deterministic reflex code only after recurrence
evidence, counterexample testing, and rollback design. This is Orange's bounded
recursive improvement loop.

## 10. Compression Plane: AtomSmasher

AtomSmasher treats the raw ledger as cold truth and builds compressed
operational views:

- commitment atoms;
- AIR structural frames;
- equations and residuals;
- cartridges;
- sparse worksets;
- least-action routes;
- expansion warrants;
- compression debt;
- saved-work certificates;
- canon pressure;
- pathwaves;
- anti-fluff decisions.

The canonical implementation is `12-ATOMSMASHER/full-scope`. Historical
module directories are primitives and cross-checks, not separate complete
engines.

Compression has distinct contracts:

- cold ledger: lossless and hash-verifiable;
- operational views: compact abstractions with source pointers;
- model boundary: bounded semantic compression.

Ratios are corpus-specific. Exact source hydration is required when proof is
needed. Compression debt records cases where compact state causes downstream
waste or recall failure.

Current Context Crystal held-out quality passed 5/5 with minimum `1422.901x`
across a 7,056,795-byte corpus. It is a workload-specific operational workbench
ratio, not a live-turn or universal byte-compression guarantee.

## 11. Visual And Creative Plane

AE Eyes is the visual-understanding facade. Captain Planet is the creative
model registry and one-specialist lease governor.

The registry separates:

- installed and runtime-artifact-proven;
- quality assessed or unassessed;
- candidate not observed.

Current image, video, speech, and music artifacts prove technical validity and
independent decoding. They do not certify studio quality.

The current lease ceiling is 50 GiB. Unknown memory is denied. Unowned models
are preserved. A model name becomes a capability only after a local artifact,
memory measurement, quality benchmark, and rollback receipt.

## 12. Storage And Evidence

- SQLite: local queryable indexes, task state, feature state, and Kanban.
- JSONL: append-only events and replayable logs.
- files: exact source, artifacts, transcripts, and cold truth.
- SHA-256 chains: mutation-evident receipt lineage.
- machine-local data: `%USERPROFILE%\OrangeBox-Data\orange5`.

SQLite is an index, not a replacement for source artifacts and append-only
receipts.

## 13. Immutable Deployment Architecture

The released Orange payload is immutable. It contains pre-authored system code,
Hermes profiles, configuration templates, schemas, and a fixed component
manifest. Setup does not grant an LLM permission to modify or synthesize any of
them.

The installation crossing is:

```text
immutable payload and fixed manifest
-> deterministic hardware/runtime discovery
-> adopt compatible Bun/Ollama/models/tools
-> present recommended selected roles
-> operator may deselect optional roles
-> explicit approval
-> automatically download missing approved components
-> verify hashes and runtime contracts
-> write mutable state to OrangeBox-Data
-> receipt
```

The LLM is a presentation and invocation surface only. It cannot add a
component, change a role, edit Hermes policy, weaken a gate, or alter the
payload. Runtime configuration, secrets, memory, receipts, logs, topology, and
download state live under `%USERPROFILE%\OrangeBox-Data`.

## 14. Security And Isolation

- loopback binds by default;
- authenticated Codexa rail;
- no credentials in source, docs, or receipts;
- explicit approval for downloads and high-risk actions;
- one writer on overlapping files;
- strict tool filtering for model and profile roles;
- model output has no receipt authority;
- candidate activation denied by default;
- no silent route or model identity change;
- no public network bind as a recovery shortcut.

## 15. Proof States

- `PROVEN`: exact runtime path has referenced evidence.
- `CONFIGURED`: implementation/configuration exists; runtime proof pending.
- `DEGRADED`: callable, with a named limitation.
- `BLOCKED`: required dependency or authority is missing.
- `FUTURE`: candidate or research only.

Documentation can describe all five states but cannot promote them.
