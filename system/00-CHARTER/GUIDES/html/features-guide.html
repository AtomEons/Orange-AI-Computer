Status Vocabulary

  • PROVEN_SNAPSHOT: a referenced historical or recent receipt proved the exact path at that time. Re-probe before relying on it now.
  • CONFIGURED_UNPROVEN: source and configuration exist; live proof is pending.
  • DEGRADED_OPERATIONAL: callable with a named limitation.
  • BLOCKED: required runtime, authority, or evidence is missing.
  • FUTURE_CANDIDATE: research or planned lane; not active.

5. Hermes And Agent Features

Current Orange Hermes surface

  • bounded leases;
  • LOOM gates;
  • approval and override auditing;
  • filesystem, process, browser, and visual adapters;
  • Misfit second opinion;
  • execution receipts.

Official Hermes Agent product integration

Configured profiles:

  • Navigator;
  • Builder;
  • Researcher;
  • Reviewer;
  • Visual;
  • Misfit.

Configured product shape:

  • one gateway owner;
  • one Kanban dispatcher;
  • one conductor and at most two specialists;
  • filtered Orange Brain MCP tools;
  • authenticated loopback OpenAI-compatible API;
  • isolated profile state;
  • no telemetry and no LAN bind.

The current integration manifest and static proof do not by themselves prove the product gateway, Kanban, and API are live. A fresh product preflight is required.

Fresh path status: Hermes Brain MCP delegation completed parent mediation, child execution, synthesis, receipts, and lease revocation in 11,409.53 ms. That proves the harmless read contract; each mutating or long-running workflow keeps its own completion proof.

8. Deployment Features

  • two-computer preferred topology;
  • single-computer supported architecture;
  • immutable Orange deploy payload;
  • pre-authored Hermes profiles and configuration templates;
  • fixed manifest with recommended defaults and optional deselection;
  • adoption of compatible installed Bun, Ollama, models, and tools;
  • automatic download of missing selected components after explicit approval;
  • all mutable runtime state under %USERPROFILE%\OrangeBox-Data;
  • hidden service expectation;
  • authenticated Codexa rail;
  • topology discovery requirement for public installs;
  • resumable, checksum-verified model downloads as the installation contract;
  • rollback-safe source and model updates;
  • optional hosted frontier lease.

Generic public clean-install, updater, and arbitrary-hardware proof must be checked in ReadyForGit. This guide does not claim those gates are closed.

9. Optional Hosted Features

OpenAI 5.6, Codex, Claude, or another strongest hosted agent may be used for:

  • guided installation;
  • architecture and code review;
  • frontier reasoning lease;
  • difficult debugging;
  • independent evidence review.

They are optional. Orange policy, memory, receipts, and deterministic execution remain local and cannot depend on a subscription.
