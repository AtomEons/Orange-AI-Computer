# OrangeFive Idea Ledger

This ledger preserves the irreducible ideas behind OrangeFive. An idea is not promoted because it sounds impressive. It remains addressable until a proof, falsifier, rejection, or return condition changes its state.

## IDEA-001: Proof-Directed Intelligence

- **Insight:** Models should propose state transitions; deterministic code should validate transitions and own truth.
- **Why:** Fluent output is not execution, evidence, or operational state.
- **Status:** implementing
- **Falsifier:** model-only control achieves equal reliability, replayability, and auditability on the same workload.
- **Next proof:** end-to-end order, route, execution, verification, and receipt roundtrip.

## IDEA-002: Capability Covenant

- **Insight:** Every request declares a minimum intelligence class; a weaker model cannot impersonate that class.
- **Why:** Silent fallback preserves uptime while destroying answer quality and operator trust.
- **Status:** implemented and production-proven on Navigator and heavy specialist routes
- **Falsifier:** shared fallback matches specialist quality and latency across held-out specialist tasks.
- **Next proof:** held-out architecture suite across multiple prompt shapes and model cold/warm states.

## IDEA-003: Context Crystals

- **Insight:** Compile a source-verifiable task workbench instead of replaying the warehouse.
- **Why:** Full context wastes time; summaries lose proof; source-addressed chunks preserve hydration.
- **Status:** implemented and active in production turns; multi-task quality parity remains open
- **Falsifier:** compressed workbench loses required authority or task quality versus full context.
- **Next proof:** quality parity benchmark across held-out project questions.

## IDEA-004: Project Continuum

- **Insight:** Preserve everything cold and exact, retrieve only the relevant lineage, and require a duplicate-work preflight before proposing new work.
- **Why:** Human and model working memory both fail over long projects.
- **Status:** implemented and active in production
- **Falsifier:** it misses an existing adapter, decision, receipt, or source during a held-out continuity test.
- **Next proof:** multi-session contradiction and supersession benchmark across interaction, receipt, and source changes.

## IDEA-005: Receipt-to-Reflex Compiler

- **Insight:** Repeated verified work should compile into bounded deterministic rules.
- **Why:** Re-asking a model to rediscover stable operational law wastes time and introduces variance.
- **Status:** operational candidate miner and falsification gate; it verifies the full spine chain, joins exact Continuum turns to receipts, requires stable repeated outcomes, runs held-out counterexamples, and forbids automatic promotion
- **Falsifier:** generated reflexes fail held-out counterexamples or cost more than model routing.
- **Evidence:** 749 spine receipts verify with no broken hashes; four trusted health-route turns across three prompt shapes have one stable output fingerprint; the first held-out run caught and repaired an unsafe edit-request match; all positive and negative holdouts now pass. - **Next proof:** mine a novel non-active candidate with three independent real uses, generate its bounded rule and regression vectors, and require explicit operator promotion.

## IDEA-006: Failure Memory

- **Insight:** Store the trigger, attempted route, falsifier, repair, and recurrence guard, not just an error string.
- **Why:** A system that records failures but repeats them has not learned.
- **Status:** implemented as bounded outcome episodes in the OpenAI-compatible gateway hot path; genuine unresolved failures are retrieved before routing, correct evidence/approval stops are not punished as mistakes, a later proven outcome closes older failures, and a new post-resolution failure reopens the episode
- **Falsifier:** future routing does not improve on replayed failure cases.
- **Evidence:** the multi-class recurrence benchmark passes 7/7: connectivity and verification successes close older episodes, post-resolution context failure reopens, correct evidence refusal is a guarded stop, capability failure remains active, query lanes remain isolated, and hot reads stay below threshold. Synthetic p95 is 1.06 ms, the live `query.chat` episode read is 57.68 ms, focused learning/gateway/recurrence tests pass 40/40, and the canonical verifier has a 169/169 clean pass. Live activation turn 751 repeated the real Hermes/Codexa route with zero active stale failures, 108 resolved failures retained as history, 186/186 learning events drained, and an exact spine-chain join. Receipts: `10-RECEIPTS/orange5-build/2026-08-26T18-48-26-497Z-failure-recurrence-benchmark.json` and `10-RECEIPTS/orange5-build/2026-08-26T19-06-07.310Z-failure-memory-live-activation.json`.
- **Next proof:** collect independent future post-deployment sessions and show a lower real recurrence rate. Live turn 749 closed the historical `query.chat` episode through a real Hermes/Codexa response; turns 750 and 751 then proved zero unresolved failures and 108 resolved historical entries without rewriting the ledger.

## IDEA-007: Current-Awareness Organ

- **Insight:** Keep current research separate from canon; quarantine and benchmark it before promotion.
- **Why:** Newness is not fitness, but stale models need verified present-day knowledge.
- **Status:** partial runtime
- **Falsifier:** bounded research cannot improve tool selection on time-sensitive held-out tasks.
- **Next proof:** compare a stale-only answer with a primary-source-aware answer and verify the selected tool locally.

## IDEA-008: Three-Speed Intelligence

- **Insight:** Reflex, Navigator, and Specialist are different computational organs, not merely model sizes.
- **Why:** Stable laws should be instant; bounded ambiguity needs a hot model; rare difficult work earns a specialist lease.
- **Status:** active
- **Falsifier:** one always-on model beats the three-speed system on latency, accuracy, cost, and continuity.
- **Next proof:** unified bakeoff across operational, conversational, architecture, and code tasks.

## IDEA-009: Operational 200x Compression

- **Insight:** Measure avoided context and avoided work while preserving source truth and task quality.
- **Why:** Byte compression alone does not reduce cognitive work; prose summaries alone lose proof.
- **Status:** actual-corpus benchmark passed for one task
- **Falsifier:** quality or exact hydration falls below the uncompressed baseline.
- **Next proof:** multi-task quality-retention benchmark and thresholded promotion.
