# OrangeFive Proof-Directed Intelligence

Status: active architecture and implementation record

Date: 2026-08-26

Product: Orange

Release: OrangeFive

## 1. The Problem

Most AI systems are organized around a model. The model receives a large replay
of context, reconstructs state in language, chooses tools probabilistically, and
returns prose. Memory, tools, verification, and orchestration are attached around
that center.

This is backwards for Orange.

A model is an expensive, temporary cognitive accelerator. It is not the computer,
the memory, the authority, the scheduler, the evidence store, or the source of
runtime truth.

OrangeFive inverts the substrate:

1. Durable state is the computer.
2. Deterministic control compiles intent into work.
3. Source-addressed memory supplies only relevant evidence.
4. Models are leased for unresolved cognition.
5. Receipts prove crossings and change future routing.
6. Repeated verified cognition crystallizes into cheaper executable law.

The interface is not the intelligence. The model is not the system. Orange is the
governed computation fabric joining operator intent, state, evidence, tools,
models, verification, and learning.

## 2. Core Architecture

Orange should operate at three speeds.

### 2.1 Reflex

Deterministic Bun code handles fixed operational truth:

- route selection
- schema repair
- capability lookup
- health endpoint selection
- memory endpoint selection
- visual-organ selection
- offline policy
- mutation proof boundaries

Reflex work uses no answer model and no broad context hydration. It still creates
an order, crosses deterministic governance, and emits a receipt. Reflex computes
from the current request and current law. It is not an answer cache.

### 2.2 Workbench

For bounded reasoning, AtomSmasher compiles a minimal source-addressed workset.
Orange then leases the smallest sufficient specialist. The work packet contains:

- active project identity and goal
- authority-ranked commitments
- current source pointers and hashes
- relevant memory
- applicable void rules and constraints
- equations or summaries when they preserve the required behavior
- explicit uncertainty
- requested output contract

The model never receives a warehouse when a workbench is sufficient.

### 2.3 Frontier

Complex architecture, novel synthesis, high-risk judgment, broad code changes,
or disputed conclusions earn a heavy lane. Hermes can divide the unresolved work
graph among specialists. A clean-context refuter challenges claim-bearing output.
The operator remains final authority.

Heavy compute belongs on Codexa. The N150 remains deterministic control, service
coordination, receipt handling, and light compilation.

## 3. Proof-Directed Work Graph

Orange should not execute a single conversational chain. Each order compiles into
a graph of unresolved edges.

Each edge has:

- a typed question or action
- authority and risk
- required evidence
- eligible organs
- estimated cost and latency
- dependencies
- completion condition
- falsifiers
- receipt identity

Deterministic organs close edges first. Existing source evidence closes the next
set. Models compete only over unresolved edges. Tools perform approved external
actions. Verification closes or reopens the graph.

This changes the meaning of orchestration. The conductor is not a chat persona.
The conductor is the graph compiler and state transition system.

## 4. Context Crystals

A Context Crystal is a task-specific, proof-carrying hot workset compiled fresh
from source truth.

It contains:

- task hash
- source-set hash
- deterministic workset id
- selected bounded source windows
- source path and character offsets
- full-source SHA-256
- selected-window SHA-256
- required-law retention proof
- raw and hot byte counts
- raw and hot token estimates
- tokens not injected
- explicit dropped-item reasons

The full source remains outside the hot context and is hydratable by pointer. A
changed source fails verification. No hidden answer cache is involved.

### 4.1 Compression Claims

Orange must report distinct metrics:

- physical context ratio: source bytes divided by hot-context bytes
- operational context ratio: estimated source tokens divided by injected tokens
- model calls avoided
- repeated work avoided
- exact byte compression for lossless encodings
- approximation error for equation packets

These numbers must never be multiplied across unrelated dimensions to manufacture
a larger claim.

The 200x target means 200x operational/context work reduction on qualifying large
corpora while preserving source access and required laws. It does not mean 200x
universal lossless byte compression.

- 3,901,653 estimated source tokens
- 9 selected source windows
- 9,613 hot bytes
- 3,846 estimated hot tokens
- 3,897,807 estimated tokens not injected

## 5. Receipt-to-Reflex Compiler

The central recursive-improvement mechanism is:

1. A new problem is solved through a model or tool once.
2. Mirror or a deterministic verifier tests the result.
3. The receipt records input shape, selected evidence, decision, failures, and
   result.
4. Orange attempts to compile the verified experience into a cheaper form:
   - deterministic rule
   - equation
   - typed transform
   - reusable route
   - small specialist adapter and eval case
5. Held-out positives and counterexamples test the candidate.
6. Only candidates with a bounded decision surface and zero surviving falsifiers
   become reflex rules.
7. Source changes, contradictions, distribution drift, or new failures demote or
   reopen the rule.

The system improves by converting verified cognition into computation. It does
not let a model rewrite itself blindly.

## 6. State Transitions, Not Answer Caching

Orange does not make cached answers its intelligence substrate.

The preferred primitives are:

- append-only events
- content-addressed sources
- explicit commitments
- equations and residuals
- deterministic state transitions
- receipt-indexed experience
- source-hash invalidation
- regeneratable derived views

An exact repeated result may be reused when its complete inputs and source hashes
are identical, but this is an optimization beneath the architecture. It is never
authority and never survives changed reality.

## 7. Recursive Learning

Learning has four levels.

### Level 1: Episodic

Record what happened, what was attempted, the evidence, the result, and the next
action.

### Level 2: Semantic

Extract durable facts, decisions, constraints, equations, preferences, and source
pointers. Conflicting facts remain separate until authority and evidence resolve
them.

### Level 3: Procedural

Compress successful work shapes into pathwaves, tool routes, and deterministic
transforms. Record failure conditions as first-class boundaries.

### Level 4: Substrate

Promote repeated verified procedures into reflex code, a constrained adapter, or
an executable equation. Measure the work avoided. Demote on contradiction.

## 8. Anti-Theater Laws

1. A cognitive report is not an executed action.
2. A generated path is not a written artifact.
3. A route decision is not a completed model call.
4. Source code presence is not runtime activation.
5. A fixture is not live infrastructure.
6. A model statement is not evidence.
7. A receipt must describe the exact path that ran.
8. A compression ratio must name its numerator, denominator, and loss model.
9. A green status must have a fresh probe for the promised behavior.
10. A fallback must identify the actual model, host, and capability reduction.

The 2026-08-26 turn audit found and repaired a contradiction where a chat-only
cognitive report was receipted as `executed: true` while the public envelope said
no execution occurred. New chat receipts now keep execution false unless a real
external action crosses the governed executor.

### 9.1 Deterministic Reflex

Five fixed operational intents now run through Bun without a model:

- health route
- project memory recall route
- visual inspection route
- Codexa-offline policy
- mutation-without-proof boundary

Live production benchmark on `127.0.0.1:1337`:

- 5/5 semantic cases
- zero model calls
- zero broad memory hydrations
- no false execution
- approximately 0.50 seconds mean end-to-end latency
- approximately 0.73 seconds p95

The earlier model path averaged approximately 5.6 seconds. The reflex path is

### 9.2 Active Limitation

Architecture-grade questions now correctly request the heavy judge lane. The

as an adequate heavy answer.

## 10. Next Runtime Organs

### 10.1 Semantic Output Gate

Before a fallback answer is accepted, compare the requested capability and the
answer against deterministic expectations:

- architecture answer must discuss the named system organs
- requested concepts must appear or be explicitly rejected
- unrelated organ drift is a failure
- substantive findings cannot be empty
- a fallback cannot silently reduce capability

Failed output returns to routing with the failure receipt attached. Orange may
lease another resident model, split the work graph, or report the exact blocker.

### 10.2 Receipt-to-Reflex Candidate Journal

Record bounded intent signatures, current source hashes, selected workset ids,
decision packets, receipt hashes, and verification outcomes. Do not store hidden
reasoning. Compile only stable observable mappings.

### 10.3 Counterfactual Shadow

For consequential routes, evaluate the cheapest plausible alternative without
executing it. Compare predicted outcome, evidence coverage, latency, and cost.
This produces training signal for routing without risking duplicate mutation.

### 10.4 Epistemic Interrupts

Allow any organ to interrupt when it detects:

- stale source hash
- unresolved contradiction
- missing authority
- model drift
- insufficient evidence
- scope divergence
- compute that no longer buys information

The interrupt reopens only the affected work-graph edge.

### 10.5 Capability Lattice

Replace static model rankings with measured capability regions. A model is not
"better" globally. It has proven competence over task shapes, context sizes,
modalities, latency bands, and failure modes. Routing selects a proven region,
not a brand name.

### 10.6 Regeneration Ledger

Store deterministic outputs as source parameters, code hash, and irreducible
residuals when regeneration is cheaper than storage. Re-run verification before
using regenerated state in a consequential decision.

## 11. Falsifiers

This architecture fails if any of the following survive testing:

- Context Crystals omit a required constraint because the task used different
  words.
- Source pointers cannot reconstruct the selected evidence.
- Reflex classification steals a request that required reasoning or execution.
- Receipt-to-reflex promotion overfits repeated but narrow examples.
- Source changes do not demote derived rules.
- Routing cost grows faster than the model work it avoids.
- The heavy lane silently falls back to a weaker model without output-quality
  enforcement.
- Receipts become expensive enough to dominate reflex latency.
- Learning stores repetition instead of new information.
- Compression lowers answer quality while reporting only token savings.

Every one of these must have an executable test, not a doctrine paragraph.

## 12. Build Order

1. Keep the production reflex compiler live and measured.
2. Keep Context Crystal source verification in ordinary project turns.
3. Add semantic output gates for architecture and other capability classes.
4. Prevent silent acceptance of under-capable heavy fallbacks.
5. Build the receipt-to-reflex candidate journal and falsifier.
6. Promote only one new learned reflex end to end.
7. Measure work avoided, quality retained, and demotion on source change.
8. Extend the work graph to Hermes specialists and counterfactual routing.
9. Repeat until model calls concentrate only on genuinely unresolved cognition.

## 13. North Star

Orange is not a chatbot harness. It is a system that turns current truth and
operator intent into the least necessary verified work.

The long-term objective is not a larger permanent model. It is a system whose
verified experience continuously changes what must be modeled at all.

Reason once. Prove it. Compile what survived. Recompute when reality changes.
