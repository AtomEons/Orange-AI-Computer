## 0. The Master Law

```
The receipt is the cold ledger. Everything operational compresses on top of it.
Compression at every layer must be lossless to truth — even if lossy in form.
Brotli LZ77 + B8 sort is the local optimum for structured JSON at this scale.
Determinism is the bigger unlock than any clever algorithm.
Recipe overhead must be smaller than the bytes it removes.
```

## 1. The Ten Laws (each verified by sha256 receipt)

### Law 1 — The Determinism Lock
Random IDs are the architectural ceiling. Replace `crypto.randomUUID()` with
`sha256(seed || index)` everywhere a unique-but-not-cryptographic identifier
suffices. **Receipt**: Exp 31, +13.4× lift (17.99× → 31.39×).

### Law 2 — Dedupe Before Transform
Hash-based exact-match collapse catches 50% of receipts before any compressor
runs. **Receipt**: Exp 36, +2.81× lift. The corpus has 3,132 unique shapes
carrying 6,224 receipts.

### Law 3 — The Shape-Diversity Rule
Decompose only when `unique_shapes / num_receipts > 0.5`. Otherwise dedupe.
- mesh.compress: 1,565 / 1,565 = 1.00 → DECOMPOSE (won +3.6×)
- air.compress: 64 / 3,126 = 0.02 → DEDUPE (decomp lost -2.4×, Exp 40)
- **Receipt**: Exp 39 (mesh wins), Exp 40 (air loses) — same logic, opposite outcomes.

### Law 4 — Brotli LZ77+B8 is Locally Optimal
Pure byte-level arithmetic coders lose by 4-10× to brotli q11 on structured JSON.
**Receipt**: Exp 60 G/H/I/J — even THEORETICAL FLOORS of order-1/2/3 byte arith
coders are 5× worse than brotli's actual output.

Implication: don't write custom byte coders. Use brotli q11 with B8 (action-bucket +
length-within) sort and call it done at the entropy-coding layer.

### Law 5 — Per-Stream Decomposition Pays Vocab Overhead
Splitting a corpus into streams costs vocab dictionaries. The crossover point
where decomposition starts winning is corpus size N >> per-stream vocab cost.
For our 6,224 receipts (~2 MB), decomposition LOST in Methods 13, 15, 16, 17.
**Receipts**: 4 falsified experiments.

Implication: at small corpus scale, monolithic brotli on B8-sorted dedupe-shape
dict is optimal. Streaming amortization needs N > ~50,000 receipts to win.

### Law 6 — Recipe Overhead Must Be < Bytes Removed
Every "extract derivation rule" approach has a recipe cost. The recipe must be
smaller than what it removes. **Receipt**: Method 13 (sum-lookup recipe 25 KB
exceeded the bytes saved → LOST 13× of compression).

### Law 7 — Generator Detection > Entropy Coding
If data is generated by a deterministic process, store the seed not the output.
**Receipt**: AIT Challenge 2026, G7-V10 reduced File D from megabytes to 14 bytes
by detecting it was glibc `rand()` and brute-forcing the seed.

For us: the replay-pipeline ceiling at 57.88× is the AtomSmasher analog. Make
the organism deterministic, transmit inputs only, decoder regenerates.

### Law 8 — Schema Folding via Derivation
If field B = f(field A), drop B and recompute on decode IFF the formula is
deterministic and the recipe is tiny. **Receipt**: Method 14, mesh.compress.ratio
= banker_round(raw / comp * 100) / 100, verified 1565/1565 matches. +1.2× lift.

WARNING: derivation formulas can vary across actions. mesh uses banker rounding;
air uses standard Math.round. **Receipt**: Method 17 falsified by wrong formula.
Always verify byte-exact across the whole population before committing.

### Law 9 — The Same Number Stored Twice Is The Big Aha
Examine every receipt for the same value appearing in BOTH summary and payload.
Brotli's LZ77 cannot catch this when values vary per-receipt. **Receipt**: Method
14, mesh.compress summary "packet #X: YB → ZB" had (Y, Z) = payload (raw, comp)
across 1,565 receipts. Dropping the redundant copy saved 4,313 B brotli'd. +4.086×
lift — the single biggest aha in this whole campaign.

### Law 10 — Lossless or Lossy by Domain, Never by Default
Different layers of AtomSmasher need different compression contracts. Audit log
bytes must be lossless byte-exact (sha256-verified). LLM context can be lossy
semantic. KV cache can be lossy attention-weighted. **The boundary between
lossless-required and lossy-acceptable must be explicit per data class.**

## 2. Per-Engine Optimization Assignments

Each AtomSmasher 2 engine gets a specific instruction based on the Ten Laws.

### 2.1 OrderSpine
- **Compression**: orders are short text; brotli alone fine
- **Aha potential**: if many orders share patterns (e.g., "execute feature X with
  config Y"), templatize per-order-template
- **Verify**: Law 8 — does any field derive from another?
- **Receipt requirement**: orders are intent — keep the cold ledger lossless

### 2.2 SourceEngine
- **Compression**: source.ingest receipts hold METADATA only (we verified — the
  actual source text is NOT in receipts). Source content lives in the cold store.
- **Aha potential**: source_id is 16-hex; if these are sha256-derived, use Law 7
- **Action**: audit how source_ids are generated. If random, replace with
  `sha256(content_hash) || normalize_url(uri)` — deterministic + content-addressed.
- **Yield**: matches Law 1 unlock for source.ingest receipts

### 2.3 CommitmentCodec (atoms)
- **Doctrine match**: "operational commitments become atoms"
- **Compression**: each atom is a small structured fact
- **Optimization**: dedupe atoms before storing (Law 2). Many commitments
  reference common entities — share via atom_ref index.
- **Pattern**: this IS Method 19's shape-dedupe applied at the semantic level
- **Yield**: atoms ARE the cartridge-compatible compressed form of commitments

### 2.4 EquationMemory
- **Doctrine match**: "numeric or structured patterns become equations"
- **Compression**: equations themselves are tiny once fitted (5-10 params)
- **Aha potential**: this is Law 8 at the doctrine level. equation = derivation
  rule for what would otherwise be many numeric samples.
- **Yield**: if a feature.execute output has 100 numeric samples fitting a line,
  store (a, b, residuals) instead of 100 values
- **Cross-reference**: this IS the technique we projected for parametric numeric
  encoding (Exp 27 axis P). The yield depends on series predictability.

### 2.5 CacheEngine
- **Compression**: cache.hit/cache.miss receipts have low cardinality
  (audit found cache key cardinality = 2 across our corpus)
- **Action**: store cache events as (key_idx, hit/miss bit) varint stream after
  the first occurrence
- **Yield**: cache event log compresses near zero per event (well below 1 byte)

### 2.6 RoutingEngine
- **Compression**: route.select decisions are categorical with small N
- **Action**: encode as varint into a route_vocab. If routes are deterministic
  function of (request_hash, context), apply Law 7.
- **Yield**: route log compresses near zero

### 2.7 SavedWork
- **Doctrine match**: "saved work is certified"
- **Compression**: saved-work records reference work products by ID
- **Action**: store the WORK PRODUCT in the cold ledger with content-address;
  store the certificate (id, sha256, status) in compressed operational view
- **Pattern**: this is the MCP-aggregation pattern at the data layer

### 2.8 MemoryImmuneSystem
- **Compression**: immune.scan receipts; defensive checkpoints
- **Action**: as informational events, follow Law 2 (dedupe identical scans)
- **Pattern**: similar to cache events

### 2.9 AgentGovernor
- **Doctrine match**: "expansion requires a warrant"
- **Compression**: warrant records are short JSON
- **Aha potential**: warrants reference (scope_from, scope_to, expires_at,
  max_uses) — many are short-lived and one-shot. Apply Law 8 — derive
  `consume_ok`, `used_count`, `remaining` from each other.
- **Yield**: 3 derived fields per warrant — small but verifiable

### 2.10 LocalProofLab
- **Compression**: prooflab.probes are structured outcomes
- **Action**: dedupe probes (Law 2) — many probes return same template
- **Note**: from our audit, prooflab.probes had 0% sum/payload overlap, so no
  Law 9 win here. Standard dedupe path.

### 2.11 FeatureExecutor (620 features)
- **The big one.** 620 feature.execute receipts per organism.run.
- **Compression**: feature outputs vary; payloads have high diversity
- **Apply Law 3**: feature.execute has 39 distinct feature names across 620
  receipts → unique_shapes/N ≈ 0.0X → DEDUPE (not decompose)
- **Apply Law 9**: 92% of summary numerics match payload values. Big chance
  for derivation. Verify formula per feature, then drop.
- **Apply Law 8**: audit found 315 functional dependencies in feature.execute
  payloads. Drop the derivable side. Each derivation rule = ~50-200 bytes
  saved per occurrence.
- **Yield**: combined Laws 2 + 8 + 9 — feature.execute could compress 3-5× more
  than baseline if all FDs land. Measure each before committing (Law 6).

### 2.12 TotalWorkCompiler (organism.run)
- **The Kolmogorov anchor.** organism.run.payload.stages contains aggregate
  snapshots of everything. This is the SEED for the replay pipeline.
- **Apply Law 7**: organism.run snapshot has enough state to regenerate the
  derived 5,331 receipts IF organism is deterministic.
- **Yield ceiling**: 1,224× (Kolmogorov), 57.88× (input-only practical)
- **Engineering required**:
  1. Replace `crypto.randomUUID()` with `sha256(seed || index)` in uniqueRuntimeId
  2. Replace `Date.now()` with seed-derived timestamps in receipt creation
  3. Audit any other `Math.random` / `performance.now` / wall-clock usage
  4. Add a "replay mode" flag that runs organism deterministically
  5. Build replay verifier: rerun and sha256-compare

### 2.13 AIRCodec
- **Doctrine match**: "verbose state becomes AIR"
- **Existing role**: AIRCodec turns prose into atoms (linguistic compression)
- **Honest measurement**: in our corpus, AIR achieved ~0.95× on its 3,126
  receipts. NOT a strong compressor — it's a STRUCTURING tool, not a
  byte-saver.
- **Don't confuse roles**: AIRCodec is for COGNITIVE compression
  (extract claims, drop filler, build atoms). Method 19 codec is for BYTE
  compression of the audit log AFTER AIR runs.
- **Cross-reference**: AIRCodec is the AtomSmasher analog of LLMLingua 2 —
  semantic content compression for downstream LLM consumption.

### 2.14 MeshStreamCompressor
- **Existing role**: compresses packet streams. Mesh.compress produces
  (raw_bytes, compressed_bytes, ratio) records.
- **Our finding**: mesh.compress receipts have full structural redundancy
  between summary text and payload — Method 14's big aha.
- **Recommendation**: keep the mesh compression algorithm as-is; have the
  TotalWorkCompiler use the Method 14 receipt-encoding pattern when persisting
  mesh.compress receipts to the audit log.

### 2.15 CrystalCompressor / CLCEngineV1POC
- **Doctrine match**: structured-pattern compression via crystal lattice
- **Existing role**: extracts entities, voids, ratios from text
- **Honest measurement**: CLC POC's ratio is highly content-dependent.
- **Pattern**: Crystal is a SEMANTIC compressor; pair it with our byte-level
  Method 19 codec at the audit-log layer.

### 2.16 WellbeingMonitor (27 Guardrails)
- **Compression**: wellbeing receipts encode (acceptance_passes, signals)
- **Action**: dedupe + per-action constant strip (most fields are constants
  per-action in healthy runs). Law 2 + Law 8.

### 2.17 PathwaveCompressor
- **Doctrine match**: "winning workflows become pathwaves"
- **Existing role**: detect repeated workflow patterns
- **This is Law 7 at the workflow level** — if a workflow is deterministic
  given inputs, encode as (pathwave_id, inputs).
- **Synergy with replay**: pathwaves ARE the replay-pipeline atoms

### 2.18 CanonPressureEngine
- **Doctrine match**: "canon emerges through pressure, not vibes"
- **Compression**: canon-detect receipts hold the canonical-claim outputs
- **Action**: canon membership is a small set; dedupe + per-claim varint index

### 2.19 EmbeddingIndex
- **Compression**: embedding.probe receipts
- **Connection to industry**: this is where TurboQuant-class techniques apply
  (1-bit / few-bit quantization of dense embedding vectors). For LOSSLESS
  byte-exact preservation of embedding vectors, use varint over float-bit-
  patterns + brotli.
- **For approximate-search use case**: TurboQuant or similar 1-bit quantization
  gives 6× memory reduction at zero accuracy loss.

### 2.20 PatternDetector
- **Compression**: pattern.detect receipts encode detected regularities
- **Action**: patterns ARE compressed representations of phenomena. Dedupe
  pattern records; reference patterns by ID.

### 2.21 ThermoLedger
- **Compression**: thermo.tick events track energy/latency
- **Action**: tick events form a time series → delta-encode timestamps,
  varint-encode values. Standard sensor-data compression.

### 2.22 MemoryPrimitive
- **Doctrine**: primitive.cool / pin / commit / retire are state transitions
- **Compression**: transitions are categorical, dedupe + varint suffices

## 3. The Hot Path — Order-to-Report Contract

The 18-step order-to-report contract is AtomSmasher's main loop. Compression
must happen at specific stations:

```
1.  Order arrives        → OrderSpine                      [no compression yet]
2.  Source ingestion     → SourceEngine                    [Law 1 on source_ids]
3.  Workset assembly     → SparseWorksets                  [Law 2 dedupe]
4.  Routing decision     → RoutingEngine                   [varint vocab]
5.  Feature selection    → FeatureExecutor                 [620 features]
6.  Cache lookup         → CacheEngine                     [Law 2, varint key index]
7.  Feature execution    → Engines (AIR/Mesh/Crystal/...)  [SEMANTIC compression]
8.  Pattern detection    → PatternDetector                 [Law 7 if deterministic]
9.  Equation fitting     → EquationMemory                  [Law 8 derivation rules]
10. Cartridge build      → CartridgeBuilder                [stable context → cold]
11. Atom commitment      → CommitmentCodec                 [Law 2 dedupe]
12. Awareness snapshot   → AwarenessSnapshot               [Law 2]
13. Wellbeing check      → WellbeingMonitor                [Law 2 + Law 8]
14. Saved work cert      → SavedWork                       [content-address]
15. Receipt emission     → TotalWorkCompiler               [Method 19 codec applies]
16. Compression debt     → CompressionDebtRecorder         [meta-tracking]
17. Canon pressure       → CanonPressureEngine             [pressure aggregation]
18. Report emission      → final output                    [LLMLingua 2 if NL]
```

Stations 1-14 are SEMANTIC compression — AtomSmasher's existing job. Station 15
is where our BYTE compression (Method 19 → 47.071×) plugs in. Station 18 is
where LLMLingua 2 plugs in for natural-language output to operator.

## 4. The Three Verified Compression Tiers

### Tier A: Cold ledger — lossless byte-exact (Method 19 territory)
- Audit logs, receipts, raw source artifacts
- **Ratio**: 47.071× verified, 57.88× projected with replay
- **Tool**: codec.mjs (this repo)
- **Roundtrip**: sha256 byte-exact

### Tier B: Operational views — lossy by abstraction
- Atoms, cartridges, equations, pathwaves
- **Ratio**: highly content-dependent; AtomSmasher engines produce these
- **Roundtrip**: NONE — these are derived views; the cold ledger is recoverable
- **Tool**: AtomSmasher engines themselves

### Tier C: LLM-boundary — lossy semantic
- Prompts to LLMs, tool returns, agent-to-agent NL messages
- **Ratio**: ~60-70% reduction at preserved semantic content
- **Tool**: LLMLingua 2 (Microsoft, verified production-ready)
- **For KV cache**: TurboQuant (Google, 6× working memory at 0 accuracy loss)

The three tiers are STACKED, not competitive. A perfect AtomSmasher run uses
all three at the right stations.

## 5. The Single Highest-Yield Engineering Move

Of everything we've measured and synthesized, ONE move dominates the next leap:

**Make `organism.run` deterministic.**

```diff
- function uniqueRuntimeId(prefix, ...parts) {
-   const tsNs = String(process.hrtime.bigint());
-   const rnd = crypto.randomUUID().replace(/-/g, '');
-   const entropy = parts.map(p => String(p)).join('|') + `|${tsNs}|${rnd}`;
-   return prefix + sha256Text(entropy).slice(0, 16);
- }
+ function uniqueRuntimeId(prefix, ...parts) {
+   const ORG_SEED = process.env.ATOMSMASHER_DETERMINISM_SEED || 'live';
+   const counter = ++globalCounter;  // monotonic per-process
+   const entropy = parts.map(p => String(p)).join('|') + `|${ORG_SEED}|${counter}`;
+   return prefix + sha256Text(entropy).slice(0, 16);
+ }
```

```diff
- const ts = Date.now();
+ const ts = ORG_SEED ? seedTime(counter) : Date.now();
```

This unlocks:
- Method 19 → 57.88× (input-only encoding) verifiable end-to-end
- Replay pipeline: rerun organism with same inputs → byte-exact regenerate
- Audit log shipping shrinks dramatically (~1.2× to 4.5× further over Method 19)
- Reproducibility: every organism.run becomes deterministically auditable
- Receipts can be regenerated from minimal seeds, matching G7-V10's 14-byte trick
  at the AtomSmasher level

The replay pipeline IS the Kolmogorov ceiling we projected at 1,224× theoretical.
